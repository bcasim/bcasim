# Legacy trace provenance

These fixtures were generated from the Java sources before this refactor
(repository revision `436fe3ce6059053830f4ee6e159ffc1819243bfc`), copied to an
isolated temporary directory. They are observations of the original simulator,
not snapshots generated by the refactored implementation.

The only instrumentation in the original simulator was:

- In `PoW`, replace the two random hash inputs with calls to one static
  `java.util.Random(1L ^ 0x5DEECE66DL)` stream, and replace the random input to
  the exponential mining delay with one static `java.util.Random(1L)` stream.
  Preserve the original delay formula and hash algorithm.
- Set `Configuration.SIMULATION_TIME` to `1000`.

A separate runner used the original initialization and event-processing methods
with two mutually connected nodes: node `0` has hashrate `0.48`, node `1` has
hashrate `0.52`, block interval is `10`, and block delay is `0`. Node `1` is
`DefaultNode` throughout. Node `0` is `DefaultNode` for `legacy-honest.json`,
`Attacker4` for `legacy-selfish.json`, and `Attacker3` for
`legacy-double-spend.json`. Each scenario ran in a fresh JVM, so all static state
and random streams started afresh. Transactions were not scheduled.

The legacy `event.json` output was parsed and formatted with two-space
indentation. Its one event with time greater than `1000` was removed: the
original queue records this event before the scheduler checks the horizon,
although it never processes that event. All fields and ordering of events at
or before the horizon were retained.

Expected event counts are 186 (honest), 208 (selfish), and 168 (double-spend).
Generation used OpenJDK 17.0.20.1 with Java 8 source/target compatibility.
