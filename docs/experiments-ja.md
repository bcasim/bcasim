# 一括実験と比較レポート

`mvn test package` でビルドし、付属の設定で60回の比較実験を実行できます。

```sh
java -jar target/bcasim-0.0.1-SNAPSHOT.jar \
  --batch examples/batch-comparison.properties --output experiments/comparison --parallel 2
```

`experiments/comparison/report.html` をブラウザで開くと、平均値・95%信頼区間・指標ごとの標本数を確認できます。グラフはSVGで、インターネット接続は不要です。`summary.csv` は1実行につき1行、`aggregates.csv` は条件・指標の組み合わせにつき1行です。CSVはヘッダー付きUTF-8で、各項目を引用符で囲んでいます。

## 条件の指定

```properties
base.config=selfish-mining.properties
seeds=1,2,3,4,5
sweep.attackerShare=0.2,0.35,0.48
sweep.blockDelay=0,2
sweep.strategy=honest,selfish
threads=2
```

`base.config` は必須で、バッチ設定ファイルからの相対パスです。`--config` と同じシミュレーション設定を使用でき、取引生成・観測ノード・時刻指定のネットワーク変更も引き継ぎます。各条件の全組み合わせを、それぞれのseedで実行します。この例では、シェア3通り × 遅延2通り × 戦略2通り × seed5個で60回です。すべての条件・戦略を検証してから出力を開始します。

| 設定 | 内容 | 省略時 |
|---|---|---|
| `base.config` | 基本のシミュレーション設定ファイル | 必須 |
| `seeds` | 重複しない整数seedをカンマで列挙 | 基本設定のseed |
| `sweep.attackerShare` | ノード0の重みのシェア（0〜1） | 基本設定の重みを維持 |
| `sweep.blockDelay` | ブロック遅延（秒、0以上） | 基本設定の遅延 |
| `sweep.strategy` | ノード0の戦略。`honest`、`selfish`、`double-spend` | 基本設定の戦略 |
| `threads` | 同時実行数（1〜256） | 1 |

シェアを指定すると、全ノードの重みの合計は1になります。ノード0に指定分を割り当て、残りを他ノードの基本設定の重みに比例して分配します。他ノードの戦略は引き継ぎます。この設定には2ノード以上が必要で、シェアが1未満の場合、他ノードの重みの合計は正数である必要があります。シェアの指定を省略すると、重みの合計も含めて元の値を維持します。項目名は攻撃者を表しますが、ノード0を `honest` にして通常採掘と比較できます。

seed・条件の重複、空の値、非有限値、未対応のキーや戦略、10,000回を超える計画はエラーになります。`--parallel N` は `threads` を上書きし、再開時に変更できます。`--batch` では `--output` が必須です。`--config`、`--seed`、`--duration` は併用できません。

## 中断した実験を再開する

```sh
java -jar target/bcasim-0.0.1-SNAPSHOT.jar \
  --batch examples/batch-comparison.properties --output experiments/comparison --resume --parallel 4
```

新規実験では、出力先が未作成または空である必要があります。マニフェストには、展開した全設定のフィンガープリント、決定的な実行ID、保存形式のバージョンを記録します。再開には同一計画と対応する保存形式が必要です。seed、条件、実効的な基本設定を変更した場合は、新しい出力先を使用してください。同じシミュレーターのビルドで再開してください。マニフェストは入力と保存形式を識別し、ソースのリビジョンまでは識別しません。

各実験は `runs/run-NNNNN-HASH/` に `event.json`、`block.json`、`metrics.json`、`configuration.properties` などの通常の結果を保存します。集計用の数値は `run-summary.properties` に記録します。出力を閉じた後、全ファイルのSHA-256ハッシュを含む `completion.properties` を最後に保存します。再開時は、この記録と内容が一致する実験のみをスキップします。

未完了・破損したディレクトリは `incomplete/` に保存してから再実行します。完了済みの実験は変更せず、上位のCSVとHTMLを計画順に再生成します。同じ出力先への同時実行はロックで防ぎます。失敗は進捗・レポートに表示し、終了コードを0以外にします。その場合も、成功済みの実験を引き継いで再開できます。

並列実行によってseed・個別出力・レポートの順序は変わりません。同時実行数を増やすと、その分の状態とログを保持するため、メモリとディスクの使用量が増えます。

## 結果の読み方

チェーンに関する指標は、設定した観測ノードの最終チェーンを基準とし、ジェネシスブロックを除外します。ノード0の採用ブロック比率、stale率、フォーク・再編、伝播遅延、攻撃の状態遷移上の成否、承認された取引数などを比較できます。各指標とモデルの制約は[日本語ガイド](japanese/doc.md)を参照してください。攻撃の成功率は状態遷移上の判定であり、競合する支払いの巻き戻しを証明する値ではありません。

レポートは条件ごとにseed間の算術平均と不偏標準偏差を計算し、Studentのt分布による平均の95%信頼区間を示します。標本数nは、その指標を定義できた成功実行の数です。比率も実行ごとに等しい重みで平均し、分子・分母を全実行で合算した比率ではありません。分母が0などで定義できない値はCSVを空欄にし、集計から除外します。0には置き換えません。標本が1個なら区間は表示しません。比率の区間も0〜1に切り詰めません。

同じseed一覧を各条件で使いますが、表示する区間は条件ごとのものです。条件差の対応あり検定や多重比較の補正、1回の実験結果の予測区間ではありません。seed数が少ない場合やまれな事象では近似が不安定になりうるため、十分な実行時間と複数seedで評価してください。
